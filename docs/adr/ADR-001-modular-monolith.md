# ADR-001: Архітектура Modular Monolith

**Статус:** Прийнято

## Контекст

Memora складається з декількох функціональних частин: автентифікації, навчальних профілів, керування знаннями, AI-обробки, генерації питань, тестування, відстеження навчального прогресу, інтервального повторення та сповіщень.

Для MVP використання окремих мікросервісів створило б додаткову інфраструктурну складність: окремі процеси розгортання, міжсервісну комунікацію, service discovery та складніше керування даними.

Водночас повністю нерозділений моноліт ускладнив би підтримку коду зі зростанням проєкту.

## Рішення

Memora реалізовано як **Modular Monolith**.

Backend запускається як один NestJS-застосунок, але функціональність розділена на окремі модулі з чіткими зонами відповідальності.

Основні модулі:

* Auth;
* Learners;
* Knowledge Collections;
* Knowledge;
* AI;
* AI Processing Logs;
* Questions;
* Quiz Sessions;
* Answers;
* Learning Progress;
* Review Schedule;
* Notifications.

Controllers відповідають за HTTP-рівень, а services містять основну бізнес-логіку. Prisma використовується для роботи з PostgreSQL. Інтеграції з OpenAI та Telegram винесені в окремі модулі.

Репозиторій організовано як monorepository з окремими директоріями:

* `backend`;
* `frontend`;
* `docs`.

## Розглянуті альтернативи

### Простий моноліт

Один застосунок без чітко визначених модульних меж був би простішим на початку, але зі збільшенням кількості функцій відповідальність компонентів ставала б менш зрозумілою.

### Мікросервіси

Мікросервісна архітектура дала б можливість незалежного розгортання та масштабування компонентів, але для поточного MVP створила б зайву операційну складність.

## Наслідки

Переваги:

* простіше розгортання;
* чіткі межі між функціональними модулями;
* простіша локальна розробка;
* відсутність необхідності у distributed communication між бізнес-модулями;
* можливість у майбутньому виділити окремі модулі в самостійні сервіси.

Обмеження:

* усі модулі працюють в одному backend-процесі;
* використовується одна база даних PostgreSQL;
* окремі функціональні частини не можуть масштабуватися незалежно.

## Результат

Modular Monolith забезпечує достатній рівень розділення відповідальності для поточного масштабу Memora та не створює інфраструктурної складності, яка не є необхідною для MVP.
