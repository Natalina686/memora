ADR-007: Генеративний AI та Human-in-the-Loop

Статус: Прийнято

Контекст

Memora дозволяє користувачу вводити інформацію природною мовою. Цю інформацію необхідно перетворити на структурований навчальний матеріал без необхідності вручну створювати flashcards або тестові питання.

Генеративний AI добре підходить для такого завдання, але результат роботи моделі не можна автоматично вважати правильним.

Рішення

У Memora генеративний штучний інтелект інтегровано через OpenAI API.

AI використовується для двох основних операцій:

структурування введеної користувачем інформації;
генерації навчальних Question на основі підтвердженого Knowledge.

Для отримання передбачуваної структури відповіді використовується Structured Outputs.

Структурування Knowledge

Перший AI-сценарій:

User Input → AI Structure → AIProcessingLog → Preview → User Approval → Knowledge

Результат AI не зберігається одразу як Knowledge.

Спочатку користувач переглядає структурований результат. Лише після підтвердження Knowledge зберігається у базі даних як навчальний матеріал.

Генерація Question

Після підтвердження Knowledge frontend автоматично запускає генерацію навчальних питань.

Другий сценарій:

Knowledge → AI Question Generation → AIProcessingLog → Question Preview → User Approval → Question

Згенеровані Question спочатку зберігаються лише як результат AI-обробки з ознакою:

approved = false

Користувач може переглянути:

формулювання Question;
варіанти відповідей;
правильну відповідь.

Лише після окремого підтвердження Question зберігаються у відповідну таблицю, а результат AI-обробки позначається як підтверджений.

Підтримувані типи Question

У поточній реалізації підтримуються:

OPEN_TEXT;
SINGLE_CHOICE;
MULTIPLE_CHOICE;
TRUE_FALSE.

Одна операція генерації створює чотири Question для одного Knowledge.

AIProcessingLog

Кожна AI-операція фіксується в AIProcessingLog.

Журнал містить:

тип операції;
input;
output;
використану модель;
статус обробки;
timestamps;
пов'язане Knowledge, якщо воно вже існує;
Account, якому належить AI-операція.

Поле accountId є обов'язковим, щоб дані AI-обробки були захищені так само, як інші персональні ресурси користувача.

Endpoint AIProcessingLog захищений JWT-аутентифікацією, а доступ до записів фільтрується за Account.

Публічного endpoint для ручного створення AIProcessingLog немає. Записи створюються лише внутрішнім AI-сервісом під час реального виконання AI-операцій.

Відокремлення від адаптивного навчання

Генеративний AI не визначає, коли Knowledge потрібно повторювати.

Його відповідальність обмежується підготовкою навчального контенту.

Інтервал повторення визначається окремою детермінованою backend-логікою на основі LearningProgress і адаптованого алгоритму SM-2.

Таким чином, генерація контенту та адаптивне планування повторень залишаються незалежними компонентами системи.

Наслідки

Переваги:

користувач зберігає контроль над AI-результатами;
некоректний або невдалий AI-результат можна відхилити до збереження;
Structured Outputs забезпечує передбачувану структуру даних;
AI-операції можна відстежувати через AIProcessingLog;
AI-дані захищені ownership-перевіркою Account;
алгоритм інтервального повторення не залежить від недетермінованого AI.

Обмеження:

система залежить від зовнішнього OpenAI API;
затримка генерації частково залежить від зовнішнього сервісу;
AI-контент усе одно потребує перевірки користувачем;
використання зовнішнього API може створювати додаткові операційні витрати.
